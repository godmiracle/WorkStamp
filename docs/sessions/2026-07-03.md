# 2026-07-03

## Session Goal

修复切到 `MapKit` 后地址显示过于泛化的问题，尽量恢复同类水印相机常见的 POI 级地点名称展示。

## What Changed

- 调整 `LocationService` 的地址拼装顺序，改为优先展示 POI 名称，再拼接门牌或道路信息
- 当 `MKReverseGeocodingRequest` 只返回门牌号或“某市附近”这类泛化结果时，增加附近兴趣点检索兜底
- 新增 POI 名称识别规则，优先保留产业园、商场、地铁站、广场、中心、大厦等更像现场地点的名称
- 完成一轮真机构建并重新安装到 `哥谭之王`
- 继续收紧兜底策略：如果没有可靠 POI，就不再保留“xx路xx号”或“上海市附近”，直接回到坐标展示
- 地点面板的“重新定位”加入显式加载态，点击后会显示“定位刷新中”
- 附近 POI 检索升级成多候选打分，并在首轮没命中时自动扩大搜索半径重试
- 恢复 `CLGeocoder` 作为第一层基础地址解析，并保留 `MapKit` 作为第二层 POI 补强
- 完成一轮新方案真机构建并重新安装到 `哥谭之王`

## Notes

- 当前实现仍然完全基于 Apple 原生 `MapKit`，没有引入第三方地图 SDK
- 当前地址链路不再是纯 `MapKit`，而是 `CLGeocoder` 保底 + `MapKit` 补强的双轨方案
- 这轮重点不是把地址变得更长，而是把“地点名”找回来，让水印更像真实到场记录
- 当前策略明显更偏向“地点可信度”，宁可退回坐标，也不展示过于泛化的地点字符串
- 当前手动刷新已经不再是“静默触发”，用户能明确感知到定位请求正在进行
- 当前 POI 选择不再只是“最近即可”，而是优先看是否更像真实地点名，再结合距离做排序
- 当前会暂时保留 `CLGeocoder` 的弃用警告，这是为中国场景地址体验做的有意识取舍
- 如果现场点位本身在 Apple 地图 POI 数据里较弱，当前更可能先显示基础地址，再视情况补到地点名

## Suggested Next Step

优先在普通街道、园区、商场、地铁口四类场景各拍一张，确认“双轨地址”是否已经比纯 `MapKit` 更稳定。
